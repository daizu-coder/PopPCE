# PopPCE 技術メモ(SHARP Brain / Windows CE)

コードは AI(Claude)が書きました。製作者はプログラムを読めません。製作者がしたのは、AI への指示と、実機(PW-G5300)での確認です。

PopPCE を作る中でわかったことのうち、実機で確かめたことと、このリポジトリのコードで裏付けが取れることだけをまとめています。Brain 向けにほかのエミュレータを移植するとき、作業を始める前に AI に読ませることを想定しています。

実機で確かめた機種は SHARP Brain PW-G5300 だけです。ほかの機種での動作は確かめていません。

速さの数字は、デバッグログ(`poppce_debug.log` の `perf:` の行)で測ったものです。各項目の最後の括弧は、製作者の手元の開発メモ(公開していません)の節と日付です。

## 描画

### 1ラインずつ描く

CE 版では、DS の 2D 機能の代わりに、アプリのコードで画面を1ラインずつ描いています(`core/pce_render.c` の `pceRenderLine`)。`core/cefix.sed` で VDC.s の `VDCDoScanline` の先頭に `core/GfxCE.s` の `ceScanlineHook` の呼び出しを入れ、表示するラインが終わるたびに、そのラインを描きます。

最初はフレームの終わりに1枚まとめて描いていましたが、実機で HuCard のゲームを動かすと、一部の場面でスプライトが 16×16 ドット単位で崩れました。1ラインずつ描くように変えて、この崩れは直りました。(開発メモ 2節・7節、2026-09-26)

### タイルキャッシュの走査を省く

VDC.s は、VRAM が書き換わった場所を `DIRTYTILES` に記録します。`core/cefix.sed` で、その書き込みと同じ値を `core/GfxCE.s` の `ceVramDirty` にも書くようにし、`core/pce_render.c` の `updateTileCaches` は、印の無いラインでは `DIRTYTILES` の走査を省きます。実機のログ(フレームスキップ 0)で、1フレームの描画の時間は 5.2〜7.9ms から 3.9〜5.3ms に、`retro_run` の平均は 17〜18ms から 14〜15ms になりました。(開発メモ 10節、2026-09-26)

## 画面への転送

ゲームの画面を 480×320 の画面に広げて書く処理は、`app/ce_display.c` の `CeDisplayBlitRGB565` です。

- 決まった比率に当たらない幅に使う汎用の経路を、2画素ずつの表引きに変えたところ、実機で write が 15ms になり、元の DDA(10ms)より遅くなりました。汎用の経路は DDA に戻しました。
- 336 幅の画面には、336 → 480(10/7)専用の経路(`s_scale10over7`)を足しました。write は 7〜9ms から 3ms になりました。320 幅(3/2 の経路)も 3ms です。

(開発メモ 10節、2026-09-26)

## コアを Windows CE で動かすための変更

### 書き込みと実行ができる区画

上流のコードは、コードと同じ区画にある変数に書き込みます(300 か所以上。例: VDC.s の `str r5,scanline`)。CE 版では、`core/cefix.sed` で、その区画を書き込みと実行ができる `.ngtext` に置きました。実機で `machineInit` が通ることを確かめました。(開発メモ 4節・5節、2026-09-26)

### BIOS の割り算

上流の `swi 0x090000`(DS の BIOS の割り算)は、`core/cefix.sed` で `core/ce_asmfix.s` の `ceBiosDiv` の呼び出しに置き換えています。呼び出し元は `bx lr` で戻るので、`lr` を退避してから呼びます。実機で `ceBiosDiv` の確認(`ceBiosDiv: OK`)が通ることを確かめました。(開発メモ 4節・5節、2026-09-26)

### ldrd / strd

ARMv5TE の決まりでは、`ldrd`/`strd` のアドレスは 8 バイト境界にそろえることになっています(PW-G5300 の CPU は ARMv5TE の ARM926)。`core/cefix.sed` で、pc 相対の `ldrd`/`strd`(VDC.s の `vdcRegPtrL`、Shared/AsmExtra.s の `rndSeed0`)を2命令に分け、各ファイルの `.ngtext` の先頭に `.balign 8` を入れて、8 バイト境界にそろえています。分けない場合の動作は確かめていません。(開発メモ 4節、2026-09-26)

## 音

### PSG のミキサーとキャッシュ

`PCEPSG/pcepsg.s` の `updateAmplitudes` は、各チャンネルの音量をミキサーの命令の即値に書き込みます。ARM926 は命令とデータのキャッシュが別なので、`core/cefix.sed` で `updateAmplitudes` の最後に `cePsgCodeChanged` の呼び出しを足し、`core/ce_stubs.c` の `ceSyncPsgCode` が `FlushInstructionCache` を呼びます。比べるのは書き換えられる 12 命令の即値の1バイトずつで、変わったときだけ同期します。(開発メモ 4節・10節、2026-09-26)

### 効果音と声

最初のビルドでは、実機で BGM だけが鳴り、効果音と声が出ませんでした。`CE/Makefile` の `ASM_DEFINES` に `-DSAMPLE_PLAYING` を足すと、効果音と声が出るようになりました。(開発メモ 7節・9節、2026-09-26)

### 44100Hz で鳴らす

`PCEPSG/pcepsg.s` の `PCEPSGMixer` は、1サンプルごとに、各チャンネルのカウンタを `PSGDIVIDE` だけ進めます(`PSGADDITION`)。カウンタの1つを PSG のクロック(3579545Hz)の1回として計算すると、上流の値の 80 は 44744.3Hz にあたります。`core/cefix.sed` でこれを 81(44191.9Hz)にし、44100Hz で再生しています。音程のずれは約 0.21%(約 3.6 セント)で、80 のまま 44100Hz で鳴らすと約 1.46%(約 25 セント)になります。(開発メモ 4節、2026-09-26)

### 再生を始める前の先溜め

音声のスレッド(`app/ce_audio.c` の `CeAudioThreadProc`)は、最初のバッファを送る前に、音声のリングに速度調整の目標の量が溜まるまで待ちます(上限 500ms)。実機のログで、ロード直後のアンダーランは 164ms・5694 サンプルから 24ms・247 サンプルになりました。(開発メモ 10節、2026-09-26)

### チャンネルの左右の音量

`core/cefix.sed` で、`PCEPSG/pcepsg.s` の2か所を変えました。

- `_0805W`(チャンネルの左右の音量の書き込み): 書き込んだチャンネルの `amplitudeChg` を立てるようにしました。mai_nurse_v1.00 のオープニングで、曲が終わったあとも音が鳴り続けていたのが、曲が終わるようになりました。
- `getVolumeDS`: チャンネルか全体の左右の音量が 0 なら、その側の音量を 0 にするようにしました。曲が終わったあとに小さな音が残っていたのが、無音になりました。

(開発メモ 15節、2026-09-28)

## フレームの速度とデバッグログ

### フレームの速度

アプリのコードでフレームの速度を調整しています(`app/ce_main.c` の `WinMain`)。実機で 60fps で動くことを確かめました。(開発メモ 6節・7節、2026-09-26)

### デバッグログの書き込み

デバッグログ(`app/ce_log.c`)は、バッファにためて、専用のスレッドがまとめて書きます。このスレッドの優先度を `THREAD_PRIORITY_BELOW_NORMAL` にすると、CD-ROM² のゲームで、`blit` の write の最大が 20〜70ms から 5〜10ms に、`retro_run` の最大がほとんどの区間で 40〜86ms から 19〜26ms になりました。(開発メモ 12節、2026-09-26)

## SuperGrafx

SuperGrafx の2つ目の VDC と VPC は、CE 版で作りました。2つ目の VDC は、`core/mkvdc2.sh` が上流の VDC.s のラベルを `<名前>_2` に変えた写しを、ビルドのたびに作ります。VPC のレジスタと I/O の振り分けは `core/SgxCE.s`、2つの画面の合成は `core/pce_render.c` の `mixVpcLine` です。VPC の動作は Mednafen(beetle-supergrafx-libretro)を参考にしました。

SuperGrafx のゲームかどうかは、拡張子が `.sgx` か、ROM の CRC32 が6件の一覧にあるかで決めます(`core/pce_core_ce.c` の `isSgxGame`)。

実機で、2枚の画面の重なり、動き、ステートセーブを確かめました。1フレームの描画の時間は、最初の版で 10.3〜14.9ms、合成を速くした版では軽い場面で 4.1〜4.3ms、重い場面で 5.5〜10.6ms でした。重い場面はフレームスキップ 0 では 60fps に届きません。最初の版では、フレームスキップ 1 で `retro_run` の平均が 13〜17ms でした。(開発メモ 11節、2026-09-26)

## CD-ROM²

### CD のイメージの読み込み

実機のログで、CD のイメージ(`.bin`)の 32KB の読み込みは1回 50〜130ms、ときどき 700〜1300ms かかりました。時間は、ファイルの中の移動の距離や向きとは関係しませんでした。そこで、読み込みを先読みのスレッド(`core/pce_cd_ce.c` の `readThreadProc`、256KB のリング)に任せ、コアはリングから写すだけにしました。スレッドの優先度を `THREAD_PRIORITY_ABOVE_NORMAL`(フレームのループより上、音声のスレッドより下)にしたあとは、コアが待った時間は1フレーム 0.0ms、16KB の読み込みは典型 9ms でした。(開発メモ 12節、2026-09-26)

### セーブ(.srm)

CD-ROM² のゲームのセーブ(バックアップメモリ)は、30 秒ごと、メニューを開いたとき、ROM を切り替えるとき、終了するときに、`app/ce_main.c` の `CeSaveSram` で保存します。中身が同じでも毎回書いていたころは、30 秒ごとの保存のたびに、実機で 0.8〜1.8 秒の途切れが出ました。前に読み込んだか保存した中身の写しと比べ、変わったときだけ書くようにして、この途切れは無くなりました。(開発メモ 12節、2026-09-26)

書き込みか `fclose` に失敗したときは、写しを無効にして、次の保存で書き直します。実機で、`fclose` をわざと2回失敗させる試験用の exe を使い、3回目の保存で書き直されること、起動し直してもセーブが残ることを確かめました。(開発メモ v1.0.4 の1回目、2026-10-09、コミット 4bfcee8・タグ v1.0.4)

### ステートセーブ

実機のログで、ステートを書き出すと、`WriteFile` は 42〜147ms で終わり、`CloseHandle` に 3.8〜6.7 秒かかりました(616,716 バイトと 2,271,500 バイト)。`app/ce_main.c` の `CeSaveState` は、`<ROM>.state.tmp` に書くところまでを行い、閉じる処理と `.state` への差し替えは別のスレッド(`CeStateWriterProc`)に任せています。次のセーブ、ロード、終了の前には、書き出しが終わるのを待ちます(`CeWaitStateWriter`)。実機で、「セーブしました」がすぐ出ること、セーブから数秒以内にロードしても正しく戻ること、セーブの直後に CD の音楽が途切れないことを確かめました。(開発メモ 12節、2026-09-26)

`core/pce_cd_ce.c` で、Arcade Card のレジスタと RAM(2MB のうち、中身が 0 でない 16KB のブロックだけ)をステートに入れています。実機で、Arcade Card を使うゲームのデモ対戦中にセーブとロードをして、表示と動きが崩れないことを確かめました。(開発メモ 12節、2026-09-26)

### cefix.sed での3つの変更

- `cdrom.s` の `updateCDROM`: `dataLen` が 0 でも `adpcmDmaOn` が残っていれば `AdpcmDMA` を呼ぶようにしました。Arcade Card を使う CD-ROM² のゲームで、デモ対戦が途中で止まっていたのが、先に進むようになりました。
- `cdrom.s` の `CD0C_R`($180C の読み出し): 読んだあとも続いている「中」の状態だけを返すようにしました。同じゲームのデモ対戦がラウンド2の試合コールのあとで止まっていたのが、最後まで進むようになりました。
- VDC.s の `vblHook`: 同じラインでラスター割り込み(RCR)と VBL が重なるときは、VBL を1ライン後に立てるようにしました。ラスター割り込みを使う CD-ROM² のゲームの対戦画面で、背景とキャラクターが正しく出ていなかったのが、正しく出るようになりました。ラスター割り込みを使うほかのゲームも、今までどおり動くことを確かめました。

(開発メモ 12節、2026-09-26)

## 画面の文字と操作

### メニューの文字

メニューの文字は Galmuri14(ビットマップフォント)を既定にしています。BDF から `CE/tools/galmuri2c.py` で `app/ce_galmuri14.h` を作り、Galmuri に無い字は東雲16の字形で埋めています。実機で東雲16・GalmuriMono11 と見比べて、Galmuri14 にしました。字を1ドット下げ、ファイル選択の一覧の行の高さを1ドット増やし(`app/ce_fileopen.c`)、ファイル選択のダイアログを上下に 4 DLU 広げました(`app/ce_res.rc` の `IDD_FILEOPEN`)。どれも実機で確かめました。(開発メモ 13節、2026-09-27)

### ファイル選択と A〜Z のボタン

ファイルを選ぶ画面で、電子辞書の A〜Z のボタンを押すと、一覧の選んでいる項目が動いていました。`app/ce_fileopen.c` の `FileListCtrlProc` で、空白以上の文字の `WM_CHAR` をリストボックスに渡さないようにしました。実機で、A〜Z を押しても項目が動かないこと、上下・左右・決定・戻るが今までどおりであることを確かめました。(開発メモ v1.0.3 の2回目、2026-10-07、コミット ea25c8b・タグ v1.0.3)

### アイコン

`CE/icon/poppce.ico` の 16×16 と 32×32 には AND マスク(透明にする部分の情報)が入っておらず、Brain の画面で、アイコンのまわりが黒くなり、左下が乱れていました。AND マスクを足して、実機で直ったことを確かめました。(開発メモ v1.0.2 の1回目・2回目、2026-10-02、コミット 3cd1beb・タグ v1.0.2)
